技術架構規劃報告

Electron + Bundled Codex App Server

本報告規劃一套簡化、本機優先的桌面 AI 應用架構：前台使用 Electron 包版， AI agent 能力由 bundled codex app-server 提供，thread / message 歷史完全交由 Codex 管理， App 僅保留必要的本機 UI 設定與 workspace 記錄。

前台技術 Electron + React + TypeScript + Vite，負責桌面 UI 與互動體驗。
AI 核心 codex app-server 隨 App bundled，作為本機 AI agent engine。
資料保存 thread / message 由 Codex 管理；App 只存 settings、workspace 與 UI state。
系統串接 第一版不做外部系統串接、不做雲端後端、不做資料庫服務。

一、核心決策

Codex App Server 與 App 一起打包 Electron 安裝後即可啟動內建 Codex binary，不要求使用者額外安裝 CLI。
歷史紀錄交給 Codex 管 thread、turn、item、message history 不自建資料表，不重複保存。
Local Workspace 優先 Codex 的工作目錄指定為使用者選擇的 workspace，檔案讀寫都在本機發生。
第一版不做外部整合 暫不接 PostgreSQL、Redis、GitHub、Jira、雲端 storage 或企業 SSO。

二、整體技術架構

本架構不另外建立傳統後端服務。Electron Main Process 作為本機控制層， 透過 stdio JSON-RPC 與 bundled codex app-server 溝通。

Electron Renderer

React UI

對話畫面、任務列表、workspace 選擇、設定頁。

State Management

只管理前端狀態與畫面狀態，不保存 AI 歷史主資料。

Electron Main Process

Preload / IPC Bridge

提供安全白名單 API，Renderer 不直接碰 Node.js。

Codex Process Manager

啟動、監控、關閉 bundled codex app-server。

JSON-RPC Client

呼叫 initialize、thread/list、thread/start、turn/start 等 API。

Bundled Codex App Server

AI Agent Engine

管理 thread、turn、item、streaming events、tool/file actions。

Codex Managed Storage

Codex 自行保存 thread / message history。

Local Workspace

以 cwd 指定工作目錄，在權限範圍內讀取與修改檔案。

三、模組責任邊界

模組 負責內容 不負責內容
Electron Renderer 畫面呈現、使用者輸入、串流訊息顯示、任務列表、workspace 操作入口。 不直接存取檔案、不直接啟動子程序、不直接呼叫 Codex binary。
Preload Bridge 暴露安全 IPC API，例如 sendMessage、listThreads、selectWorkspace。 不暴露完整 Node.js / Electron API 給 Renderer。
Electron Main 管理 Codex 子程序、JSON-RPC 通訊、workspace path、local app config、事件轉發。 不自行實作 AI agent、不自行保存完整 message database。
Codex App Server AI 對話、thread / turn / item、串流事件、auth、sandbox、workspace 檔案操作。 不負責客製化 UI、不負責 Electron 視窗與桌面行為。

四、資料保存策略

因為 thread / message 歷史完全交給 Codex 管理，所以 App 不需要設計 message table 或本機 SQLite。 App 僅保存 UI 與 workspace 相關的輕量設定。

App 自行保存

app-local-data/ ├── settings.json ├── workspaces.json └── ui-state.json

範例設定

{ "lastWorkspace": "/Users/user/project-a", "recentWorkspaces": [ "/Users/user/project-a", "/Users/user/project-b" ], "theme": "system" }
重點： App 可以透過 thread/list 向 Codex 取得任務列表，不需要自行維護 thread / message 主資料。 若未來 UI 需要搜尋或分類，可以再補一層輕量 index，但第一版不建議先做。

五、啟動流程

1 App Ready

Electron 啟動，Main Process 初始化。

2 Spawn Codex

從 resources 目錄啟動 bundled codex app-server --stdio。

3 Initialize

Main 送出 JSON-RPC initialize，建立連線上下文。

4 Read Account

呼叫 account/read 確認登入與 auth 狀態。

5 UI Ready

Renderer 顯示 workspace、thread list 與可操作狀態。

六、AI 對話資料流程

1 使用者輸入

Renderer 收到使用者訊息。

2 IPC Request

Renderer 透過 Preload 呼叫 Main 的 sendMessage。

3 turn/start

Main 對 Codex app-server 送出 turn/start。

4 Streaming Events

Codex 回傳 delta、tool progress、completed 等事件。

5 畫面更新

Main 將事件轉成 IPC stream，Renderer 即時顯示。

Codex 常用 JSON-RPC 方法

方法 用途
initialize 建立 client 與 app-server 連線上下文。
account/read 讀取目前登入與帳號狀態。
thread/list 取得 Codex 管理的 thread / task 清單。
thread/start 建立新的對話 / 任務，可指定 cwd 為 workspace。
thread/resume 恢復既有 thread，繼續對話。
turn/start 送出使用者輸入並開始 AI agent 執行。
turn/interrupt 中斷進行中的 AI 回合。

七、Bundled Codex 注意事項

因為 Codex binary 會跟 App 一起包版，因此建置與更新流程要把 binary 視為 App runtime 的一部分。

  • macOS、Windows、Linux 需要放入各平台對應的 Codex binary。
  • Electron 打包時將 binary 放在 resources 或指定 unpacked 目錄。
  • App 啟動時以 process.resourcesPath 定位 binary。
  • macOS / Linux 需要確認 binary 具備可執行權限。
  • Windows 需要處理 codex.exe 路徑與防毒誤判風險。
  • auto update 時，App 與 Codex binary 版本應一起更新。
  • JSON-RPC schema 建議跟 bundled binary 版本綁定，避免 protocol mismatch。

八、MVP 功能範圍

Workspace 選擇 Codex 啟動 Auth 狀態 Thread List Thread Start Thread Resume Turn Start Streaming Reply Turn Interrupt Local Settings

第一版不納入

  • 外部系統串接，例如 GitHub、Jira、Slack、Drive。
  • 雲端後端 API server。
  • PostgreSQL / Redis / S3。
  • 自建 message database。
  • 多人協作與企業管理後台。

九、結論

本案建議採用 Electron UI + Electron Main 本機控制層 + bundled Codex App Server 的架構。 這樣可以最大化沿用 Codex 既有 AI agent 能力，並避免第一版過早導入後端系統、資料庫與外部整合。

最終定位是：Electron 負責包版與使用者體驗；Codex app-server 負責 AI agent、thread/message 歷史、 workspace 操作與 streaming events；所有專案資料保留在 local workspace。
